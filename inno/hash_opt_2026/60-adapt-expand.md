## 1. 动机

HASH_EXPAND sweep(为冲 c-64 翻面)发现 docs/47 的旧经济学已翻:1.4 在 retry 重载阵上净赢
(c-64 −4.1%/c-62 −1.9%/c-62ghs −3.0%),且 bcsstk30 的旧回归(+6.8%)在 v23 retry 机制下
**反转为大赢(−17.8%)**;但 Ga3As3H12 +13.5%(1.4 治不了它的 overflow,只放大表)。
⇒ 判别器 = "1.4 能否把 overflow 减半"——只能跑起来才知道 ⇒ **运行时自适应**。

## 2. 机制(per-process 状态机)

```
状态 0(基线 1.15):轮末 overflow>50 行 → 记基线计数,状态 1
状态 1(升 1.4):  轮末 overflow×2 > 基线(没减半)→ 状态 2;否则保持

```
二进制每次调用 5 warmup + timed 轮 → 第 3 轮收敛,后续全在收敛值;CSV 取末轮 = 收敛值。
假试成本 ≈ 一轮(会自动回退)。

## 5. 状态机 v2/v3 修订(08-30 晨,commit afcc261;⚠ 未净窗验证)

**v1 缺陷暴露**:v26 全量揭出 13 个"受害者"(inline_1/c-big/Flan_1565 +45%、F2 +28% …)——
"overflow 减半即保留"误升大表矩阵:overflow 确实减半,但 est×1.22 → 表上一档 → 大表矩阵
吞吐直接受伤。而 rajat25(9 亿 nnz 赢家)与 cage15(9.3 亿 受害者)同规模 ⇒ 规模门无效。

**v2(时序判据)**:1.4 轮的已计相位和 > 1.15 轮 ×1.05 → 回退。缺陷 = **暖机偏置**:run2(1.4)
永远比 run1(1.15)暖 → F2(实测 1.4 慢 23%)被误留。

**v3(相邻轮对比 = 进程内交替协议,当前版本)**:
```
0(1.15)→ ovf>50 → 1(试 1.4,记 t)→ 3(回测 1.15,记 t')→ t ≤ t'×1.02 ? 4(定 1.4) : 2(定 1.15)
```
相邻两轮同暖度 → 偏置消除;5 warmup+timed 轮内第 4 轮收敛。
